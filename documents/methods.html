02   데이터와 비교 단위

분석의 단위부터
해석의 경계를 정한다.

공모전 소비자료는 월·지역·업종·고객 속성별 집계다. 관측된 비중을 비교할 수 있지만 개인의 이동 순서나 특정 점포의 실제 전체 매출을 직접 알 수는 없다.

입력분석에 쓰는 내용해석상 주의
소비 집계업종별 금액·건수, 월별 관측, 연령·외국인 구분BC 이용 실적의 집계이며 전체 시장과 다름
상가정보점포 수, 업종 매핑, 좌표와 직선거리카드 업종과 공공 업종 분류가 다름
인구정보규모·연령 구성과 소비구조의 비교거주 인구와 결제 인구는 일치하지 않음
정책 지정인구감소·관심지역 등 적용 맥락지정 여부 자체가 효과의 근거는 아님

집계 전에 확인하는 항목

  1. 입력 파일의 버전·지문과 컬럼 정의를 고정한다.
  2. 지역·업종 표기를 정규화하고 중복 키와 누락 코드를 확인한다.
  3. 금액과 건수를 분리해 합계를 대조한다.
  4. 같은 비교에서 기간·업종 범위·모집단 분모를 통일한다.
미상을 조용히 지우지 않는다.
연령 미상 행을 제거하면 성별·외국인 비중의 분모까지 달라질 수 있다. 각 지표에서 포함·제외한 범위를 별도로 설명한다.

공개본에서는 무엇을 다르게 했는가

원자료의 일부를 추출하거나 숫자에 잡음을 더하지 않았다. 가상 지명과 시연용 수치를 직접 작성해 비교와 판정 흐름을 보여 준다. 따라서 공개 예제의 개수·통과율·수치는 실제 제출 분석의 결과로 해석할 수 없다.

공식 데이터 설명의 기간은 2026년 1~6월이며, 제공 업종 범위 안에서 지표를 해석한다. 원본 제출물의 지역별 결과표와 회귀 기준값은 공개하지 않는다.

03   LQ와 앵커 제외 CLQ

분모를 바꾸는 이유를
계산으로 확인한다.

LQ는 지역에서 해당 업종이 차지하는 비중을 비교 모집단의 비중으로 나눈 값이다. 1을 넘으면 비교 범위에서 상대적인 비중이 크다는 뜻이며, 생산성이나 성장률을 직접 나타내지 않는다.

LQ = (지역 파트너 / 지역 총액)
     ÷ (비교 파트너 / 비교 총액)

앵커 업종의 비중이 특히 크면 나머지 업종이 상대적으로 작아 보인다. CLQ는 지역과 비교 모집단에서 앵커를 모두 제외한 후 파트너의 비중을 다시 비교한다.

CLQ = [지역 파트너 / (지역 총액 − 지역 앵커)]
      ÷ [비교 파트너 / (비교 총액 − 비교 앵커)]

가온시 합성 예제 · 임의 금액 단위

구분총액제과점(앵커)일반한식(파트너)
지역1,000400220
비교 모집단10,0001,0002,500
보정 전
0.88

(220/1,000) ÷ (2,500/10,000)

앵커 제외 후
1.32

(220/600) ÷ (2,500/9,000)

구현에서 놓치기 쉬운 지점

지역 분모에서만 앵커를 빼면 비교 기준이 달라져 잘못된 값이 나온다. 금액과 건수에도 같은 정의를 적용한다. 분모가 없거나 비교 업종 값이 0이면 임의의 큰 점수 대신 계산 불가로 처리한다.

공개 코드: analysis/metrics.py의 location_quotient·conditional_lq. 예제 재계산과 한쪽 분모만 제거하는 오류를 구분하는 테스트를 제공한다. 이 값은 후보 자격을 설명하며 할인 효과를 입증하지 않는다.

04   후보와 제외 이유

좋은 점수 하나로
선정을 끝내지 않는다.

소비기반이 있어도 관측이 짧거나 연결할 점포가 없으면 실행하기 어렵다. 조건을 순서대로 적용하고, 어느 단계에서 판단을 멈췄는지 남긴다.

확인 단계질문부족할 때의 처리
앵커 실체거래·점포 기반이 있는가?앵커 후보에서 제외
파트너 자격금액·건수·관측 조건을 충족하는가?조건별 제외 이유 기록
역행 검토강한 역행을 의심할 근거가 있는가?탐색 규칙·불확실성 함께 기록
공급 확인해당 업종의 점포 집합을 식별할 수 있는가?매핑이 모호하면 추가 확인
공간 조건주변에 연결할 점포가 충분한가?거리 조건 미달 또는 보행 확인

선정 결과와 현장 확인을 분리한다

점포 좌표로 계산한 500m는 직선거리다. 실제 보행 경로·횡단·진입 가능성을 나타내지 않는다. 공급 확인에서는 비슷한 업종을 합쳐 센 점포 수를 특정 업종의 확정값처럼 사용하지 않는다.

한정식 공급이 모호한 예시
공공 분류가 일반한식과 한정식을 합친다면, 점수가 높아도 한정식 점포를 확정할 수 없다. 시연에서는 수치를 대신 채우지 않고 ‘공급 확인’으로 남긴다.

차순위도 함께 남기는 이유

1순위와 차순위의 격차가 작으면 작은 입력 변화로 순서가 바뀔 수 있다. 운영 담당자는 순위뿐 아니라 격차·제외된 후보·현장 조건을 함께 읽어야 한다. 대기열과 확정 승인을 같은 표시로 보여 주지 않는 이유다.

공개 시연의 판정 함수는 흐름을 설명하는 축약 예제다. 관측 3개월·CLQ 1·거리 충족 비율 50% 같은 시연 조건을 코드에 명시했다. 비공개 전체 파이프라인의 모든 규칙을 재현했다고 주장하지 않는다.

05   생활재·연령 관점

검토 범위를 넓혀도
조건은 생략하지 않는다.

생활재 소비를 별도로 보는 이유

목적형 소비의 대표 업종을 찾을 때에는 생활재를 분리할 수 있다. 그러나 지역의 일상 소비에서 생활재가 중요한 출발점이라면 별도 트랙으로 검토할 가치가 있다. 이때 집단 간 비중 차이가 단순히 연령구성에서 비롯된 것은 아닌지 함께 살핀다.

보정 비중 = Σ (연령별 생활재 비중 × 공통 연령 가중치)
합성 연령층 1 · 2

생활재 비중: 20%, 60%
공통 가중치: 75%, 25%

같은 구성으로 재가중
30%

0.20 × 0.75 + 0.60 × 0.25

이 계산은 구성 차이를 줄여 비교하는 예제다. 관측되지 않은 소득·근로·방문 목적까지 통제하는 인과 추정은 아니다. 없는 연령층을 조용히 제외하고 가중치를 바꾸지 않는다.

전체 평균에서 연령 조건으로

다온시 합성 사례는 제과점이 전 연령 금액 CLQ 0.80에서 별도 연령 1.20으로 바뀌는 상황을 가정한다. 건수 CLQ도 함께 확인하되, 기본 후보의 점포·거리 결과를 이 후보에 복사하지 않는다.

판단기록 방식
전체 기준 자격 부족기본 후보로 채택하지 않음
별도 연령 조건 충족연령 실험 후보로 분리
제과점 공급·거리 미확인추가 확인, 수치는 미확인으로 유지

지역 선택과 개인 타기팅의 구분

집계자료의 외국인·연령 지표는 지역과 업종의 검토에 쓰인다. 이를 이용해 개인의 국적이나 직업을 추정하는 기능은 구현하지 않았다. 실제 혜택의 적격 조건과 동의 범위는 운영 단계에서 별도로 정해야 한다.

06   불확실성을 다루는 태도

동조성은 연결 효과의
증거가 아니다.

고객구성이 비슷하다는 것과 함께 성장한다는 것은 다르다. 월별 지표가 같이 움직인다고 해서 같은 개인이 두 업종을 연속으로 이용하거나, 할인이 추가 소비를 만들었다고 말할 수도 없다.

관계가 보일 때 함께 확인할 것

점검확인하려는 문제
한 달씩 제외특정 월에 따라 상관의 부호·크기가 크게 달라지는가?
순열검정월의 대응을 바꾼 결과와 관측 관계를 비교하면 어떤가?
부트스트랩관측을 재표집했을 때 관계의 불확실성은 어느 정도인가?
다중비교후보를 많이 검토하면서 우연한 관계를 선택한 것은 아닌가?
시간 분할앞 기간의 선택이 뒤 기간에도 유지되는가?
짧은 관측기간에서의 해석
6개월 자료라면 월을 하나 빼는 것만으로도 판단이 크게 변할 수 있다. 순열검정과 재표집을 적용해도 짧은 기간·계절성·선택 편향의 한계가 사라지는 것은 아니다.

탐색 규칙과 확정 근거를 구분한다

역행 후보를 제외하는 규칙을 사용하더라도, 다중비교 이후의 결과와 불확실성을 함께 설명해야 한다. 강한 양의 상관을 곧바로 ‘연계 할인 효과’라고 해석하지 않는다. 전체 자료를 본 뒤 나눈 시간 분할 역시 독립적인 미래 검증과 구분한다.

지표로 검토 범위를 줄이고,
실험으로 효과를 확인한다.

공개 데모의 ‘역행 가정’은 이 분기 동작을 보여 주기 위한 합성 입력이다. 실제 p값·신뢰구간이나 실증 결과를 싣지 않았다. 공개 계산 예제에서도 상관·효과 검정을 실행한 것처럼 표시하지 않는다.

공개판은 직접 작성한 9개 합성 예시를 포함한다. 원본의 전체 원장이나 실제 지역 판정을 복제하지 않는다. 웹사이트의 ‘HTML 다운로드’로 저장하면 오프라인에서도 같은 조회·출력 기능을 사용할 수 있다.

주체별 역할

지자체

할인 재원 마련, 참여 가맹점 협의, 사업 목적과 현장 조건 확인. 결과를 근거로 후속 사업 범위를 판단한다.

BC

데이터 진단, 실험 설계·운영, 효과측정. 지역마다 다른 조건에서 연결 규칙의 적용 가능성을 축적한다.

사업비 가정은 견적과 구분한다

제출 제안에서는 지역당 진단·실험 용역을 약 3인월로 두고 인월 단가 600만~1,000만 원을 가정했다. 이에 따른 1,800만~3,000만 원은 기획 단계의 산정 예시이며, 확정 계약·매출·시장 견적이 아니다. 고객 할인비와 공통 시스템 개발비는 별도로 검토한다.

효과가 검증되기 전의 사업화
공통 코드를 재사용할 수 있어도 지역별 효과가 자동으로 재현되는 것은 아니다. 후속 지역마다 소비구조·가맹점·표본·운영비를 다시 확인해야 한다.

혜택 전달 수단과 BC 서비스 연동은 협의가 필요한 제안이다. 실제 계약·운영 승인·도입 실적이 있는 것으로 표현하지 않는다. 기존 BC 서비스의 전체 기능을 비교한 문서도 아니다.

09   실증 설계

비교 대상을 바르게 잡아야
연결의 기여가 보인다.

연결할인과 무개입만 비교하면 할인 자체의 효과와 업종 연결의 효과가 섞인다. 일반 지역할인을 주요 비교군으로 두고, 같은 비용과 노출 조건에서 차이를 확인한다.

A · 무개입혜택 없음
B · 일반할인지역 가맹점군
C · 연결할인선정 파트너
안내군파트너 안내만

주요 비교: C−B

앵커 거래 조건을 충족한 적격 회원을 지역별로 층화해 무작위 배정하는 안이다. 할인액·사용기간·메시지 노출을 가능한 한 맞춘다. 배정 후 72시간 지역 전체의 후속 BC 결제액을 비교하고 최초 앵커 거래는 제외한다.

쿠폰을 쓴 사람만 비교하지 않는다

쿠폰 사용자만 분석하면 원래 반응 가능성이 높은 사람이 선택될 수 있다. 주 분석은 사용 여부와 관계없이 배정된 회원 전체를 대상으로 한다. 정보만 제공하는 안내군은 보조 비교로 사용한다.

실행 전 확정확인할 내용
대상과 기록이용권한·동의·식별자 처리, 중복 배정 방지, 거래·혜택 로그
실험 운영표본 수, 배정창·관측창, 할인 한도, 오염·누락 대응
의사결정검정·추정 기준, 비용 대비 효과, 중단·확대 규칙

평가에서도 범위를 제한한다

측정되는 것은 해당 조건에서의 BC 후속 결제다. 현금·타사 카드까지 포함한 지역 전체 경제효과와 같지 않다. 회원 간 정보 공유나 가맹점 간 영향이 있을 수 있어 운영 방식에 맞는 추가 검토도 필요하다.

실험은 설계 단계다. 실제 무작위 배정, 쿠폰 발행, 소비 증가 측정은 수행하지 않았다. 표본·예산은 실제 동의 고유 회원 수와 변동성에 따라 실행 전에 다시 계산해야 한다.

10   공개 코드와 출처

구현한 범위와
남은 검증을 함께 공개한다.

구분내용
만든 것분석·선정 규칙, 근거 원장, 제출 문서, HTML 조회·검토서 시제품
공개하는 것이 설명서·공개 소개서·합성 데모·핵심 계산 예제·테스트
공개하지 않는 것공모전 원자료, 실제 지역별 수치·원장·회귀 기준값, 원본 제출 PDF
미검증개인 교차구매, 실제 보행·참여 가맹점, 할인 효과·도입 성과

공개 예제의 재현 방법

python -m analysis.synthetic
python -m unittest discover -s tests -v
python scripts/build.py

계산 예제와 테스트는 Python 표준 라이브러리를 사용한다. 공개 PDF 재생성에는 WeasyPrint와 한글 글꼴이 필요하다. 공개 예제는 제출 분석 전체를 재현하지 않으며, 실제 원자료 없이 실행할 수 있는 방법·동작 예제다.
