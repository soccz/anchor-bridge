02   입력과 비교 단위

자료를 연결하기 전에,
같은 대상을 보고 있는지 확인한다.

소비 집계는 월·지역·업종·고객 속성의 조합이다. 공공 상가 좌표는 실제 점포의 공급을 확인하는 자료다. 두 자료는 관측 단위와 업종 분류가 다르다.

입력분석에 쓰는 내용먼저 확인할 차이
소비 집계업종별 금액·건수, 월, 연령·집단 구성BC 이용 실적이며 전체 시장과 다름
상가정보점포 수, 업종 매핑, 좌표카드 업종과 공공 업종 분류가 다름
인구정보규모·연령 구성의 비교거주 인구와 결제 인구가 다름
정책 지정상권 지원의 적용 맥락지정 여부는 효과의 증거가 아님

같은 합계에서 출발하는 계산

→
정규화·매핑지역·업종·중복 키
→
분모 대조기간·업종·집단 일치

입력 버전과 컬럼 정의를 고정하고, 지역 코드·업종 표기를 맞춘다. 금액과 건수의 합계를 각각 대조하며 기간과 제공 업종 범위를 동일하게 유지한다. 미상 행을 제외했다면 그 이유와 제외 범위를 지표별로 기록한다.

관측한 것

지역·업종별 소비 비중과 구성
공공 분류상 점포와 직선거리
정해진 규칙의 자격·제외 이유

별도로 확인할 것

개인의 연속 구매·실제 보행
가맹점 참여·데이터 이용권한
연계 할인이 만든 추가 소비

데이터가 없으면 모르는 상태로 남긴다.
불명확한 점포 매핑을 0으로 처리하거나, 다른 업종의 점포 수로 채우면 서로 다른 문제가 같은 판정으로 섞인다. 공급 확인과 거리 미달을 별도로 기록한다.

공식 소비자료 설명의 기간은 2026년 1~6월이다. 이 공개 예제는 원자료의 일부를 추출하거나 교란한 값이 아니며, 직접 작성한 집계와 가상 지역만 사용한다.

03   앵커 제외 LQ

매출을 늘린 것이 아니라,
비교의 분모를 바꾼 것이다.

가온시에서 제과점이 소비의 큰 부분을 차지한다고 가정한다. 일반한식의 상대 비중을 전체 소비 기준으로 볼 때와 제과점을 제외하고 볼 때를 비교한다.

합성 집계 · 임의 금액총액제과점일반한식
가온시1,000400220
비교 모집단10,0001,0002,500

전체 소비 기준

가온시22.0%
비교 모집단25.0%
0.88

LQ = (220 / 1,000)
÷ (2,500 / 10,000)

양쪽에서 제과점 제외

가온시36.7%
비교 모집단27.8%
1.32

CLQ = (220 / 600)
÷ (2,500 / 9,000)

CLQ = [지역 파트너 / (지역 총액 − 지역 앵커)]
÷ [비교 파트너 / (비교 총액 − 비교 앵커)]

한쪽 분모만 바꾸면 다른 지표가 된다

지역에서만 제과점을 빼면 비교 모집단과 기준이 달라진다. 금액과 건수에 같은 정의를 적용하고, 두 축의 자격을 함께 확인한다. 분모가 없거나 비교 업종 값이 0이면 임의의 큰 점수 대신 계산 불가로 남긴다.

기준 1을 넘으면 비교 범위에서 상대적인 비중이 크다는 뜻이다.
이 값만으로 생산성·성장률·할인 효과를 해석하지 않는다. 후보 자격을 검토하는 계산으로 사용한다.

코드: analysis/metrics.py의 location_quotient, conditional_lq.
테스트: 양쪽 분모 제거, 단위 변경 불변성, 0·잘못된 입력, 보정 전후의 자격 변화를 확인한다.

04   선정·제외·보류

좋은 점수 하나로
실행을 결정하지 않는다.

후보의 소비기반과 실행 조건을 나누어 확인한다. 기준 미달과 정보 부족을 같은 상태로 표시하지 않고, 판단을 멈춘 이유를 남긴다.

확인 단계확인하는 문제판단에 남기는 내용
앵커 실체거래·점포 기반이 있는가출발 업종의 자격
파트너 자격금액·건수·관측 조건을 충족하는가부족한 축과 관측 기간
월별 관계역행을 의심할 근거가 있는가탐색 규칙과 통계적 불확실성
공급 매핑해당 업종의 점포 집합을 식별하는가확정 수치 또는 공급 확인 보류
공간 조건주변에 연결할 점포가 충분한가직선거리 조건과 보행 확인 과제

같은 화면에 다른 이유를 남긴다 · 합성 예시

후보확인된 조건현재 판정
가온시 · 일반한식자격·공급·거리 조건 충족검토 후보
가온시 · 스넥자격은 충족, 강한 역행을 가정탐색적 제외
가온시 · 한정식점포 집합을 별도 식별하지 못함공급 확인
해온군 · 제과점관측이 1개월뿐인 상황관측 부족
직선거리와 보행 경로는 다르다.
좌표로 500m 안에 있는 점포를 셀 수 있어도 횡단·진입 가능성이나 가맹점 참여를 확인한 것은 아니다. 공급이 모호한 업종은 거리 통과로 표시하지 않는다.

차순위와 미확인 조건을 함께 검토한다

1순위와 차순위의 차이가 작다면 작은 입력 변화로 순서가 바뀔 수 있다. 선정 이유뿐 아니라 대안과 현장 조건을 읽을 수 있게 해, 추천 결과를 확정 승인으로 받아들이지 않도록 설계했다.

공개 판정 함수는 축약 예제다. 관측 3개월·금액과 건수 CLQ 1·거리 충족 비율 50% 등의 시연 조건을 명시했다. 역행 여부는 가정한 입력이며 실제 유의성 검정 결과가 아니다. 비공개 전체 규칙을 재현하지 않는다.

05   생활재·연령 보정

구성 차이를 줄이고,
대상이 바뀐 효과를 구분한다.

생활재 · 같은 연령구성으로 다시 비교

두 집단의 생활재 소비 비중이 다르더라도 연령구성 차이가 섞여 있을 수 있다. 아래는 두 연령층으로 만든 독립 합성 예제다.

집단연령층별 생활재 비중원래 연령 가중치전체 비중
A20% / 60%20% / 80%52%
B10% / 30%60% / 40%18%
원래 구성의 비중 차이
34%p

52% − 18%

공통 가중치 60% / 40%
18%p

A: 20%×60% + 60%×40% = 36%
B: 10%×60% + 30%×40% = 18%

코드: standardized_share. 없는 연령층을 조용히 제외하고 가중치를 다시 맞추지 않는다. 관측하지 않은 소득·방문 목적까지 통제하는 인과 추정은 아니다.

연령 · 관측대상을 먼저 맞춘다

전체 집계에는 연령 미상 결제가 포함되고 특정 연령에는 포함되지 않을 수 있다. 다음 예제는 다온시 사례와 별도로, 비교 집단 변경만으로 자격이 바뀌는 상황을 보여 준다.

전체 0.80미상 포함
→
확인 집단 1.05미상 제외
→
특정 연령 1.20연령 조건
이 예제는 연령을 고르기 전에 이미 기준 1을 넘는다.
0.80 → 1.20 전체를 연령 보정의 기여로 설명하면 과장이다. 같은 관측대상의 전체 지표도 기준 미만인지 확인한 뒤 연령 조건의 자격 변화를 구분한다.

연령 조건에서 자격을 얻더라도 기본 후보의 공급·거리 결과를 복사하지 않는다. 파트너 업종이 다르면 점포 집합을 다시 확인하고 별도 실험 후보로 남긴다.

코드: diagnostics.eligibility_change. 공개 시연의 다온시 사례는 연령별 자격 변화와 미확인 공급을 설명하는 가정이며, 실제 집단의 보정 효과가 아니다.

06   관계와 예측의 검증

그럴듯한 관계가
다른 질문의 답은 아닌가.

① 월별 움직임이 개인의 연결을 뜻하지는 않는다

두 업종이 같은 방향으로 움직여도 같은 사람이 연속으로 결제했다는 뜻은 아니다. 짧은 계열은 한 달에 따라 관계가 바뀔 수 있으므로 한 달씩 제외하고, 순열·재표집·다중비교를 함께 점검해야 한다.

한 관측에 의존하는 관계 · 별도 합성 반례
X = [1, 2, 3, 10]
Y = [3, 2, 1, 10]

전체에서는 양의 상관이지만 마지막 관측을 빼면 완전한 음의 상관이 된다. 방향 하나만 보고 후보를 확정하면 이 불안정성을 놓친다.

correlation과 leave_one_out으로 실행한다. 시연의 합성 6개월 선과는 다른 검증 반례다.

② 지역을 나누어도 시간 누수가 남을 수 있다

제출 분석의 예측 실험을 검토하며 지역 단위 분할만으로 미래 예측을 입증할 수 없음을 확인했다. 같은 결과 기간의 다른 지역 정답으로 학습하면 예측 시점에 없던 정보를 사용할 수 있다.

require_available_before는 명시된 특징·학습 정답의 이용 가능일을 검사한다. 모든 누수를 자동 탐지하는 기능은 아니며, 실제 데이터 계보와 학습 절차를 별도로 점검해야 한다.

예측력이 있어도 연계 할인의 효과를 대신하지 않는다.
원래 성장할 업종을 고르는 질문과 손님을 연결하면 소비가 늘어나는지 묻는 질문은 다르다. 효과 판단은 무작위 비교 실험에 둔다.

공개 코드에는 위 반례의 테스트를 포함한다. 원본 모형·성능 수치·실제 지역별 통계 결과는 공개하지 않는다.

담당자의 입력이 바꾸는 것과 바꾸지 않는 것

체크 상태와 메모는 검토서에 포함된다. 화면을 새로고침하면 사라지므로 보관하려면 인쇄 또는 PDF 저장을 사용한다. 확인 표시를 했다는 이유로 분석 판정이나 운영 승인 상태를 바꾸지는 않는다.

CSS·스크립트·합성 데이터가 HTML 하나에 포함된다. 설치·계정·서버·외부 데이터 파일 없이 실행한다. 혜택 발행·개인 동선 추적·실제 효과측정 기능은 구현하지 않았다.

08   서비스 운영과 사업화

지역 진단부터 사업 평가까지,
단계별 판단 자료를 제공한다.

지자체의 상권 지원사업에 소비 진단·후보 선정·실험·효과측정을 묶어 제공하는 용역 모델을 제안한다. 할인 재원과 분석·운영 용역비는 구분한다.

단계제공 내용남기는 산출물
지역 진단소비구조·대표 업종 검토지역별 진단 리포트
후보 검토자격·제외·공급 조건 정리후보 원장·현장 검토서
실험 운영대상·혜택·배정·기간 설계운영 명세·실행 조건
효과 평가일반할인 대비 후속 소비 비교효과·비용·확대 또는 중단 근거

지자체

할인 재원을 마련하고 참여 가맹점을 협의한다. 지역 사업의 목적과 현장 조건을 확인하고, 결과에 따라 후속 사업 범위를 판단한다.

BC

데이터 진단, 실험 설계·운영, 효과측정을 담당하는 안이다. 지역마다 다른 조건에서 연결 규칙의 적용 가능성을 검증한다.

사업비는 가정과 확정 견적을 구분한다

지역당 진단·실험 용역의 기획 가정
1,800만~3,000만 원

약 3인월 × 인월 600만~1,000만 원.
고객 할인비와 공통 시스템 개발비는 별도 검토한다.

이 금액은 제출 제안의 산정 예시이며 확정 계약·매출·시장 견적이 아니다. 데이터 이용 조건, 가맹점 협의 범위, 운영 기간을 확정한 뒤 실제 견적을 산정해야 한다.

재사용할 것은 절차, 다시 확인할 것은 지역별 효과

공통 코드를 재사용할 수 있어도 후속 지역의 효과가 자동으로 보장되지는 않는다. 지역별 소비구조·공급·모집 규모·운영비를 다시 확인하고, 효과와 비용을 근거로 확대 여부를 판단한다.

BC 서비스 연동과 혜택 집행 수단은 협의가 필요한 제안이다. 도입·계약·운영 승인을 받은 서비스로 소개하지 않으며, 기존 BC 서비스 전체 기능을 비교한 문서도 아니다.

09   효과를 확인할 비교 실험

같은 할인 조건에서
연결의 추가 기여를 묻는다.

연결할인과 무개입만 비교하면 할인 자체와 업종 연결의 효과가 섞인다. 일반 지역할인을 주요 비교군으로 두고 지역 전체의 후속 BC 결제를 비교한다.

A · 무개입혜택 없음
B · 일반할인지역 가맹점군
C · 연결할인선정한 파트너
안내군같은 파트너 안내만
C − B
같은 비용 조건에서 연결의 기여를 확인한다.

앵커 거래 조건을 충족한 적격 회원을 지역별로 층화해 무작위 배정하는 안이다. 할인액·사용기간·메시지 노출을 가능한 한 맞춘다. 배정 후 72시간 지역 전체의 후속 BC 결제액을 비교하며 최초 앵커 거래는 제외한다.

쿠폰을 쓴 사람만 비교하지 않는다

쿠폰 사용자만 분석하면 원래 반응 가능성이 높은 사람이 선택될 수 있다. 주 분석은 사용 여부와 관계없이 배정된 회원 전체를 대상으로 한다. 안내군은 정보 제공의 효과를 확인하는 보조 비교로 사용한다.

실행 전 확정확인할 내용
대상과 기록이용권한·동의·식별자 처리, 중복 배정 방지, 거래·혜택 로그
실험 운영표본 수, 배정창·관측창, 할인 한도, 누락·집단 간 영향
판단 기준추정·검정, 비용 대비 효과, 중단·확대 규칙
측정하는 것은 해당 조건에서의 BC 후속 결제다.
현금·타사 카드까지 포함한 지역 전체 경제효과와 같지 않다. 파트너 업종의 증가가 다른 업종의 감소와 함께 나타나는지도 살핀다.

실험은 설계 단계이며 실제 회원 배정·혜택 발행·효과 측정은 수행하지 않았다. 표본과 예산은 실제 배정창의 동의 고유 회원 수와 변동성으로 재산정한다. 연령 조건의 추가 가치는 기본 연결과 구분한 별도 실험으로 검토한다.

예제 실행

python -m analysis.synthetic
python -m unittest discover -s tests -v
python scripts/build.py

계산과 테스트는 Python 표준 라이브러리를 사용한다. 생성된 site/demo/index.html을 직접 열면 시연이 작동한다. PDF 재생성에는 WeasyPrint와 한글 글꼴, 브라우저 검증에는 Chrome과 README의 도구가 필요하다.

핵심 계산과 검증의 공개 예제다.
비공개 전체 분석 파이프라인의 재현 패키지가 아니다. 실제 원자료·지역별 수치·원장·회귀 기준값·원본 제출 PDF는 포함하지 않는다. 원본 분석 성능이나 지역 추천을 공개 합성 값으로 대신 주장하지 않는다.
